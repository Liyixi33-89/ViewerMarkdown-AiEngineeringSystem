## 1. 系统架构总览

### 1.1 架构风格

前后端分离；前端两个路由域（前台门户 `/`、后台管理 `/admin`）共用一个 SPA 工程；后端按「公开只读接口」与「管理鉴权接口」双通道划分。

```
                    ┌─────────────────────────────┐
   访客（浏览器） ──▶│  前端 SPA（React 构建产物）      │
   管理员（浏览器）─▶│  /        前台预览门户（只读）    │
                    │  /admin   后台管理中心（鉴权）    │
                    └───────────┬─────────────────┘
                                │ HTTPS（REST / WebSocket）
                    ┌───────────▼─────────────────┐
                    │  Nginx（静态托管 + 反向代理）    │
                    └───────────┬─────────────────┘
                                │
                    ┌───────────▼─────────────────┐
                    │  后端服务（Spring Boot 单体）    │
                    │  ├─ portal  公开只读接口        │
                    │  ├─ admin   管理鉴权接口        │
                    │  └─ ws      变更推送（M2）      │
                    └──────┬──────────────┬────────┘
                           │              │
                    ┌──────▼─────┐  ┌─────▼──────────┐
                    │  MySQL 8   │  │ 本地磁盘/对象存储  │
                    │（业务数据）   │  │（导入导出临时文件） │
                    └────────────┘  └────────────────┘
```

### 1.2 请求链路与数据流

1. 前台访客：`浏览器 → Nginx → /api/portal/**`（只读，无鉴权），数据仅含 `PUBLISHED` 且未删除节点。
2. 后台管理员：`浏览器 → Nginx → /api/admin/**`（JWT 鉴权），全量数据（含草稿、回收站）。
3. 同步：M1 前台每 10s 轮询 `/api/portal/version`（版本时间戳）；M2 升级 WebSocket 推送变更事件。

### 1.3 技术选型汇总

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 前端框架 | React 18 + Vite 5 + TypeScript 5 | 双路由域单工程，`React.lazy` 分包 |
| 路由 | React Router 6 | `/` 与 `/admin` 两棵路由树 |
| 状态管理 | Zustand | docTree / auth / viewerPrefs 三个 store |
| 组件库 | Ant Design 5（仅后台） | 前台阅读区自研样式，不受管理端风格影响 |
| Markdown 渲染 | react-markdown + remark-gfm + rehype-sanitize + react-syntax-highlighter | 双端复用同一渲染管线 |
| 扩展渲染 | KaTeX（rehype-katex）、Mermaid（动态 import） | 按需异步加载 |
| HTTP 客户端 | Axios（拦截器统一鉴权与错误处理） | — |
| 后端框架 | Spring Boot 3.2 + Java 17 | 单体分层架构 |

```tsx
// routes/guard.tsx
function RequireAuth({ children }: { children: JSX.Element }) {
  const token = useAuthStore(s => s.token);
  if (!token) return <Navigate to="/admin/login" replace />;
  return children;
}
```

### 2.3 核心：Markdown 渲染管线（双端复用）

```tsx
// components/markdown/MarkdownViewer.tsx（示意）
import ReactMarkdown from 'react-markdown';
import remarkGfm from 'remark-gfm';
import rehypeKatex from 'rehype-katex';
import rehypeSanitize, { defaultSchema } from 'rehype-sanitize';
import { Prism as SyntaxHighlighter } from 'react-syntax-highlighter';

const sanitizeSchema = {
  ...defaultSchema,
  // 白名单扩展：允许 class（供代码高亮/TOC锚点），禁止 script/iframe/event
  attributes: { ...defaultSchema.attributes, code: ['className'], span: ['className'] },
};

function MarkdownViewer({ content, theme }: { content: string; theme: 'light' | 'dark' }) {
  return (
    <ReactMarkdown
      remarkPlugins={[remarkGfm]}
      rehypePlugins={[[rehypeSanitize, sanitizeSchema], rehypeKatex]}
      components={{
        code: CodeBlock,          // 高亮 + 一键复制
        img: ImageViewer,         // 灯箱预览
      }}
    >
      {content}
    </ReactMarkdown>
  );
}
```

要点：

1. **XSS 防护**：`rehype-sanitize` 白名单过滤，默认 schema 已禁 script/iframe/事件属性；渲染层不再使用 `dangerouslySetInnerHTML`。
2. **大文档性能**：内容 >200KB 时分片懒渲染（按一级标题切块，`IntersectionObserver` 逐块挂载）；代码块与 Mermaid 均 `dynamic import`。
3. **一致性**：前台与后台预览共用 `MarkdownViewer`，主题通过 `data-theme` 属性 + CSS 变量切换。
4. **Mermaid 降级**：渲染失败时显示源码 `<pre>` 块 + 错误提示，不白屏。

### 2.4 状态管理（Zustand）

| Store | 职责 | 持久化 |
| --- | --- | --- |
| `docTreeStore` | 树数据、选中 id、展开集合、（后台）脏标记 | localStorage（折叠/选中） |
| `authStore` | accessToken / refreshToken / 管理员信息 | localStorage（加密可选） |
| `viewerPrefsStore` | 主题、字号、回显宽度、每文档滚动位置 | localStorage |

```ts
// stores/docTreeStore.ts（示意）
interface DocNode { id: number; parentId: number | null; name: string; type: 'FOLDER' | 'DOC'; sortOrder: number; hasChildren?: boolean }

export const useDocTreeStore = create<DocTreeState>()(
  persist(
    (set, get) => ({
      nodes: [], selectedId: null, expanded: new Set<number>(),
      select: (id) => set({ selectedId: id }),
      load: async () => set({ nodes: await portalApi.getTree() }),
    }),
    { name: 'mdv-tree', partialize: (s) => ({ selectedId: s.selectedId, expandedArr: [...s.expanded] }) }
  )
);
```

### 2.5 关键交互实现方案

| 需求 | 方案 |
| --- | --- |
| 树内筛选（P1） | 对扁平列表做前缀匹配，命中节点及其祖先链自动展开 |
| 上传对话框 | 文件 Tab：`<input type="file" multiple accept=".md,.markdown">`；粘贴 Tab：受控 textarea + 防抖 300ms 触发预览 |
| 重名处理 | 前端展示后端返回的最终名（后端追加 `(1)`），不自行拼接 |
| 自动保存（后台编辑，P1） | 停笔 2s 防抖触发 `PUT /admin/docs/{id}`；失败本地草稿（localStorage）+ 顶部红条提示 |
| 滚动位置记忆 | `viewerPrefsStore` 记录 `docId → scrollTop`，切换文档时还原 |
| 前台同步（M1） | `usePolling` 每 10s 请求 `/api/portal/version`，时间戳变化则刷新树与当前文档 |
| TOC 高亮同步（P1） | 从渲染结果抽取 h1-h3 构建 TOC；`IntersectionObserver` 监听标题进入视口切换高亮 |

### 2.6 前台响应式设计（PC + 移动端）

前台门户需同时适配 PC 与移动端浏览器（响应式 Web，一套代码）；后台 `/admin` 仅保证 PC 端体验。

#### 2.6.1 断点策略（Mobile First）

| 断点 | 宽度 | 布局形态 |
| --- | --- | --- |
| Mobile | <768px | 单栏：顶栏（汉堡菜单）+ 全屏内容；目录树为**全屏抽屉** |
| Tablet | 768–1279px | 单栏正文 + 抽屉树；正文边距收窄（16px） |
| Desktop | ≥1280px | 完整三栏：顶栏 + 左树 + 回显区（左栏可折叠） |

#### 2.6.2 移动端交互方案

| 场景 | PC 方案 | 移动端方案 |
| --- | --- | --- |
| 目录导航 | 左侧常驻树 | 汉堡按钮 → 全屏抽屉（含搜索框），选中后自动关闭 |
| 搜索 | 顶栏常驻搜索框 | 顶栏图标 → 展开搜索层（全宽） |
| 代码块复制 | hover 显示复制按钮 | 代码块右上角常显复制按钮；横向滑动查看 |
| 表格超宽 | 横向滚动条 | 横向滚动（`-webkit-overflow-scrolling: touch`），首列可固定（P2） |
| TOC 大纲 | 右侧悬浮面板 | 底部浮动按钮唤起半屏抽屉式大纲（P1） |
| 图片灯箱 | 点击放大 | 点击放大 + 双指缩放 + 左右滑动切换（P1） |
| 回显宽度 | 800px 居中 | 流式 100% - 32px 边距；字号 15px（PC 16px） |
| 滚动位置记忆 | localStorage | 相同实现；移动端额外记忆抽屉开合状态 |

#### 2.6.3 技术实现要点

1. **断点检测**：`useMediaQuery('(min-width: 768px)')` 自研 hook（matchMedia 监听），不引入额外依赖；断点常量集中在 `utils/breakpoints.ts`。
2. **viewport 配置**：`<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">`；配合 `env(safe-area-inset-*)` 适配刘海屏/底部手势条。
3. **布局实现**：三栏用 CSS Grid `grid-template-areas`；移动端切换为单 `main` 区域 + 抽屉（复用同一 `DocTree` 组件，容器由布局层决定）。
4. **主题变量**：字号/行高/边距全部走 CSS 变量，断点内覆写变量值而非重写样式。
5. **触摸体验**：所有可点击区域 ≥44×44px；抽屉支持触摸滑动关闭（自研 touch 事件或 framer-motion，P2）；禁用长按选中正文图片（`-webkit-touch-callout`）。
6. **移动端性能**：树 >200 节点时抽屉内启用虚拟滚动；图片 `loading="lazy"`；Mermaid/KaTeX 保持动态 import 不阻塞首屏。
7. **桌面缩放兼容**：支持 Ctrl+滚轮缩放（浏览器默认行为不干预）；`rem` 布局单位确保缩放后不错乱。

#### 2.6.4 移动端验收标准

1. iPhone SE（375px）/ iPhone 14 Pro / Android 主流机型（360–412px）无横向溢出（除代码块/表格有意滚动）。
2. 抽屉树打开/关闭流畅，选中文档后自动关闭并渲染正文。
3. 100KB 文档在移动端中端机型（如骁龙 7 系）渲染 ≤800ms。
4. 触摸滚动全程无卡顿；固定顶栏无抖动（`overscroll-behavior` 处理边界回弹）。

### 2.7 前端性能预算

| 指标 | 目标 |
| --- | --- |
| 前台首屏 JS（gzip） | ≤250KB（不含 AntD；AntD 仅在 admin chunk） |
| 文档渲染（50KB） | PC ≤300ms；移动端中端机型 ≤800ms |
| 树 1000 节点 | 虚拟滚动（react-window / AntD Tree virtual），首渲染 ≤1s |
| 切换文档 | 复用已加载内容缓存（LRU，容量 20 篇） |
| 移动端 Lighthouse | Performance ≥85（中端机型模拟） |

### 3.2 数据库设计

```sql
-- 文档树节点（文件夹与文档统一建模）
CREATE TABLE doc_node (
  id          BIGINT PRIMARY KEY AUTO_INCREMENT,
  parent_id   BIGINT NOT NULL DEFAULT 0 COMMENT '父节点，0=根',
  name        VARCHAR(200) NOT NULL,
  type        TINYINT NOT NULL COMMENT '1=FOLDER 2=DOC',
  content     MEDIUMTEXT COMMENT 'Markdown 原文，仅 DOC',
  status      TINYINT NOT NULL DEFAULT 1 COMMENT '1=PUBLISHED 2=DRAFT',
  sort_order  INT NOT NULL DEFAULT 0,
  deleted     TINYINT NOT NULL DEFAULT 0 COMMENT '软删除（回收站）',
  deleted_at  DATETIME NULL,
  created_by  BIGINT NULL,
  created_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  KEY idx_parent (parent_id, deleted, status),
  KEY idx_name (name)
);

-- 后台管理员（与前台访客无关）
CREATE TABLE admin_user (
  id            BIGINT PRIMARY KEY AUTO_INCREMENT,
  username      VARCHAR(50) NOT NULL UNIQUE,
  password_hash VARCHAR(100) NOT NULL COMMENT 'BCrypt',
  role          VARCHAR(20) NOT NULL DEFAULT 'EDITOR' COMMENT 'SUPER_ADMIN/EDITOR',
  created_at    DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  last_login_at DATETIME NULL
);

-- 版本历史（P2）
CREATE TABLE doc_version (
  id         BIGINT PRIMARY KEY AUTO_INCREMENT,
  doc_id     BIGINT NOT NULL,
  content    MEDIUMTEXT NOT NULL,
  created_by BIGINT,
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  KEY idx_doc (doc_id, created_at)
);

-- 站点设置（P2，KV）
CREATE TABLE site_setting (
  skey   VARCHAR(50) PRIMARY KEY,
  svalue VARCHAR(500)
);
```

设计说明：

1. **单表物化路径辅助**：高频「按前缀查子树」（删除/移动校验/zip 导入）增加 `path` VARCHAR(1000) 冗余列（如 `/1/5/12/`），`LIKE '/1/5/%'` 一次命中整棵子树，避免递归查询。
2. 内容不落文件系统，统一 MEDIUMTEXT（上限 16MB，覆盖 PRD 的 2MB 限制）。
3. 软删除统一 `deleted` 标记；前台所有查询强制 `deleted=0 AND status=1`。

### 3.3 REST API 设计

统一响应：`{ "code": 0, "msg": "ok", "data": ... }`；非 0 为业务错误码；HTTP 层面 401/403/404 由全局异常处理器映射。

| code | 含义 |

### 3.4 关键服务逻辑

#### 3.4.1 上传解析（UploadService）

```
入口：multipart(.md) 或 JSON(text)
  → 校验：扩展名 .md/.markdown、大小 ≤2MB、UTF-8 可解码（拦截二进制伪装）
  → 标题：文件名去扩展名 / 正文首个 # 标题 / "未命名"
  → 重名：同目录同名自动追加 "(n)"，返回最终名
  → 内容预处理：统一换行符为 \n；截断尾部空白
  → 入库（事务）+ 版本戳自增 → 返回 {id, finalName}
```

#### 3.4.2 移动与排序校验（NodeService）

1. 目标不能是被移动节点自身或其子树（`path` 前缀判断：`target.path LIKE concat(node.path, '%')` 拒绝）。
2. 目标必须是 FOLDER；层级深度 = 目标深度 + 子树高度 ≤5。
3. 移动更新子树所有 `path`（一次 UPDATE ... REPLACE 或批量重算，子树大时分批提交）。
4. 完成后自增版本戳。

#### 3.4.3 删除与回收站（RecycleService）

```
软删除：node.deleted=1 + deleted_at=now，整棵子树同样标记（path 前缀批量）
前台过滤：所有 portal 查询 WHERE deleted=0 AND status=1（MyBatis 拦截器统一注入）
恢复：若原父已删除/不存在 → 提升到根目录；重名自动追加后缀
物理删除：定时任务每日扫描 deleted_at < now()-30d 的节点，连带 doc_version 清理
```

#### 3.4.4 前后台同步（M1 轮询 → M2 WebSocket）

```java
// sync/VersionRegistry.java（M1）
@Component
public class VersionRegistry {
    private final AtomicLong version = new AtomicLong(System.currentTimeMillis());
    public long current() { return version.get(); }
    public void bump() { version.updateAndGet(v -> Math.max(v + 1, System.currentTimeMillis())); }
}
// 任何 admin 写操作成功后调用 bump()；portal 只读 VersionRegistry
// M2：bump() 同时向 /topic/change 广播 {type, nodeId}，前台订阅后增量刷新
```

### 3.5 认证与安全

| 项 | 方案 |
| --- | --- |
| 密码存储 | BCryptPasswordEncoder（强度 10） |
| Token | jjwt；AccessToken 2h、RefreshToken 7d；Refresh 可吊销（内存黑名单 + 定期落库） |
| 接口防护 | `/api/portal/**` permitAll（只读无敏感）；`/api/admin/**` hasRole(EDITOR/SUPER_ADMIN) |
| 上传防护 | 后缀白名单 + 内容 UTF-8 探测 + 2MB 限制；文件名 `StringEscapeUtils` 清洗后入库 |
| CORS | 白名单域名；开发期 `localhost:5173`（Vite 默认端口） |
| 防 XSS 双保险 | 前端 rehype-sanitize 渲染层消毒；后端入库前对 content 不做转义（保留 Markdown 原文），输出端信任前端消毒 + 接口仅返回纯文本 |
| 限流 | 门户搜索接口 IP 维度简单限流（Guava RateLimiter，10 QPS） |
